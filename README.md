# ไปไหนดี

เว็บช่วยตัดสินใจว่าจะกิน/เที่ยวที่ไหน — เน้น *แนะนำ* ไม่เน้นพิมพ์ค้น: เลือกอารมณ์ ("หิวแล้ว ใกล้ ๆ", "คาเฟ่นั่งชิล"…) ปรับนาที/เกณฑ์รีวิว แล้วดู "แนะนำตอนนี้" หรือกด "ตัดสินใจให้เลย"

## โครงสร้าง (ออกแบบให้เพิ่มจังหวัด/ประเทศได้)
| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | หน้าเว็บทั้งหมด ไฟล์เดียว เปิดได้เลย |
| `config.js` | ตั้งค่า: Google Maps key, ภูมิภาคเริ่มต้น, ปุ่มแนะนำ (presets) |
| `regions.js` | **นิยามภูมิภาค** ชื่อ จุดศูนย์กลาง รัศมี ภาษา สกุลเงิน โหมดเดินทาง คำค้น — ใช้ทั้งหน้าเว็บและ `collect.py` |
| `data/<region>.js` | ข้อมูลสถานที่ต่อภูมิภาค (`data/chiangmai.js` ตอนนี้เป็น **ข้อมูลตัวอย่าง**) |
| `collect.py` | ดึงข้อมูลจริง: `python collect.py chiangmai` |
| `photos/<region>/` | รูปที่สคริปต์โหลดมา |

### เพิ่มพื้นที่ใหม่
1. เพิ่ม object ใน `regions.js` (มีตัวอย่าง `chiangrai`, `tokyo` ไว้แล้ว — ต่างประเทศตั้ง `travelMode: "TRANSIT"` ได้)
2. `python collect.py <id>` → ได้ `data/<id>.js`
3. เลือกพื้นที่จาก dropdown ในหน้าเว็บ — ที่สนใจ/ทริป/ร้านที่เพิ่มเอง แยกเก็บต่อพื้นที่

## แผนที่
ตอนนี้ใช้ OpenStreetMap (Leaflet, ไม่ต้องมี key) ใส่ `googleMapsKey` ใน `config.js` (เปิด **Maps JavaScript API** + **Directions API**) แล้วจะสลับเป็น Google Maps อัตโนมัติ และในหน้าทริปจะวาดเส้นทางจริงพร้อมนาทีจริงระหว่างจุดแทนค่าประมาณ
> ถ้าต้องการใช้ Advanced Markers/สไตล์จาก Cloud ให้ใส่ `googleMapId` ใน config ด้วย (ไม่บังคับ)

## อัปขึ้นออนไลน์ (ใช้บนมือถือตอนเที่ยว)
เป็นเว็บ static + serverless function 1 ตัว (`/api/resolve` สำหรับ "แปะลิงก์แล้วให้ระบบไปเช็คต่อ") รองรับทั้ง Netlify และ Vercel โดยไม่ต้องแก้อะไร
- **Netlify**: ลากโฟลเดอร์ทั้งหมดไปที่ app.netlify.com/drop หรือเชื่อม git → ตั้ง env `GOOGLE_MAPS_API_KEY` (และ `ANTHROPIC_API_KEY` ถ้าอยากให้สรุปรีวิว) ใน Site settings → Environment variables
- **Vercel**: `vercel` ในโฟลเดอร์ หรือเชื่อม git → ตั้ง env เดียวกันใน Project settings
- Google Maps JS key ใน `config.js` เป็น key ฝั่งเบราว์เซอร์ **ต้องจำกัด HTTP referrer** ให้เป็นโดเมนของเว็บ ส่วน key ฝั่งเซิร์ฟเวอร์ (env) ไม่ต้องใส่ในไฟล์
- ที่ถูกใจ/ทริปยังเก็บใน localStorage ต่อเครื่อง → มือถือกับคอมไม่ซิงก์กัน (ขั้นถัดไปถ้าต้องการแชร์กับแฟนแบบสด ๆ ต้องเพิ่ม backend เช่น Supabase)

## ใช้ร่วมกันหลายเครื่อง/หลายคน (Supabase)
1. supabase.com → New project → SQL Editor → วางเนื้อหา `supabase.sql` แล้ว Run
2. Settings → API → คัดลอก **Project URL** และ **anon public** key ใส่ `supabaseUrl` / `supabaseAnonKey` ใน `config.js` → deploy
3. เปิดเว็บ → ปุ่ม "ใช้ร่วมกัน" → "สร้างพื้นที่ร่วม" → คัดลอกลิงก์ (`?space=...`) ส่งให้อีกคนเปิดครั้งเดียว
ทุกเครื่องที่เปิดลิงก์เห็น ที่ถูกใจ / ทริป / ร้านที่เพิ่มเอง ชุดเดียวกันแบบทันที (realtime) และแต่ละรายการบอกว่าใครเพิ่ม
ความปลอดภัยอยู่ที่ id ยาวสุ่ม 18 ตัว: ใครมีลิงก์ก็แก้ได้ เหมาะกับใช้ในครอบครัว ไม่เหมาะกับแชร์สาธารณะ

## แชร์ลิสต์กับแฟนผ่าน Google Maps
Google ไม่เปิด API ให้เพิ่มลง "รายการที่บันทึก" ของบัญชีโดยตรง มี 2 ทางที่ทำได้จริง
1. ปุ่ม **"＋ ลิสต์ Google Maps"** บนการ์ด → เปิดร้านนั้นใน Google Maps (ตรงตัวเมื่อมี place_id) → กด "บันทึก" → เลือกลิสต์ที่แชร์ร่วมกัน (2 แตะ)
2. แท็บ **ที่สนใจ → "ส่งออก KML"** → นำเข้าใน Google My Maps ได้เป็นชั้นแยกตามหมวด แล้วแชร์ลิงก์ My Maps ให้แฟนดูบนมือถือได้

## ดึงข้อมูลจริง
```bash
pip install requests anthropic
export GOOGLE_MAPS_API_KEY=...   # เปิด Places API (New) + Routes API
export ANTHROPIC_API_KEY=...     # ไม่ตั้ง = ข้ามการสรุปรีวิว
python collect.py chiangmai
```
สคริปต์จะ: ค้นตาม seeds → ดึงรายละเอียด/รีวิว/ที่จอดรถ → คำนวณนาทีจากจุดศูนย์กลาง (Routes) → ให้ Claude สรุปเมนูเด่น/ไฮไลท์/ข้อควรระวัง/ปีที่เปิด → คำนวณใกล้เคียง/ผ่านทาง → เขียน `data/<region>.js`
ถ้ามี `manual.<region>.json` (ส่งออกจากแท็บ "เพิ่มร้านเอง") จะค้นร้านเหล่านั้นเพิ่มให้ด้วย

## เกณฑ์รีวิว 2 โหมด
- **คะแนนถ่วงน้ำหนัก** — ค่าเฉลี่ยเบย์: (v/(v+m))·R + (m/(v+m))·C, m = 100 (ปรับใน `index.html`)
- **ยอดนิยม** — กรองด้วยจำนวนรีวิวขั้นต่ำล้วน ๆ (100 → 10,000) ไม่ถ่วงน้ำหนัก เรียงตามจำนวนรีวิว

## ฟีเจอร์ส่วนตัว (localStorage แยกต่อพื้นที่)
- ♥ ที่สนใจ · ทริป (จัดลำดับ ประเมินนาที เปิดเส้นทางทั้งทริป แนะนำที่แวะใกล้จุด ส่งออก JSON) · เพิ่มร้านเอง (ชื่อ + ลิงก์ + โน้ต อ่านพิกัดจากลิงก์ Google Maps ได้)

## ข้อกำหนด Google
- `place_id` เก็บได้ถาวร ข้อมูลอื่นควรรีเฟรชไม่เกิน 30 วัน → รัน `collect.py` เป็นประจำ
- ต้องแสดงเครดิต Google เมื่อโชว์ข้อมูลจาก Places และรูปมี attribution ใน API response
